# Qodana — Quality Gate para Long Method

**Número de aluno:** 129841  
**Ferramenta:** Qodana  
**Inspeção escolhida:** `Long Method`  
**Parâmetro:** `NonCommentSourceStatements`  
**Limite:** `m_limit = 30`

## 1. Objetivo

O objetivo desta tarefa é configurar um quality gate no GitHub Actions, utilizando o Qodana, para detetar métodos Java excessivamente longos.

A inspeção `Long Method` permite identificar métodos que devem ser considerados para refatorização, contribuindo para a legibilidade e manutenção do código.

## 2. Configuração

Foi configurada a inspeção `Long Method`, utilizando a métrica `NonCommentSourceStatements` e o limite de 30 instruções.

O workflow do GitHub Actions executa automaticamente a análise Qodana nos Pull Requests.

Quando é detetada uma violação com a severidade definida para o quality gate, a execução falha.

## 3. Evidências — Red → Green

### Red — Execução com violação

Foi introduzida uma violação da inspeção `Long Method`, ultrapassando o limite configurado de 30 instruções.

O Qodana identificou um problema de severidade elevada, provocando a falha do quality gate.

**Resultado:** FAILURE

## 4. Reflexão

O Qodana permite detetar automaticamente métodos excessivamente longos, ajudando a identificar código que poderá beneficiar de refatorização. No entanto, o número de instruções não determina, por si só, a qualidade ou complexidade de um método. Por isso, os resultados da ferramenta devem ser analisados em conjunto com a legibilidade, a responsabilidade e a organização do código.
