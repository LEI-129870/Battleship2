# Checkstyle — Convenções de Identificadores

**Número de aluno:** 129841  
**Regra escolhida:** `MethodName`  
**Convenção:** lowerCamelCase  
**Pull Request:** [PR #24](https://github.com/LEI-129870/Battleship2/pull/24)

## 1. Objetivo

O objetivo desta tarefa é garantir automaticamente que os nomes dos métodos Java respeitam a convenção lowerCamelCase, utilizando o Checkstyle integrado num workflow do GitHub Actions.

## 2. Configuração

Foi criado o ficheiro `checkstyle-129841.xml`, contendo exclusivamente a regra `MethodName`, com a seguinte expressão regular:

`^[a-z][a-zA-Z0-9]*$`

Esta expressão obriga os nomes dos métodos a começar por uma letra minúscula, permitindo letras e números nas posições seguintes.

O workflow `.github/workflows/checkstyle-129841.yml` utiliza a action `dbelyaev/action-checkstyle@v3`, disponível no GitHub Marketplace, para executar automaticamente a verificação nos Pull Requests.

Quando é detetada uma violação, o quality gate falha.

## 3. Evidências — Red e Green

### Green — Execução sem violações

O workflow foi executado com os nomes dos métodos em conformidade com a regra definida.

**Resultado:** SUCCESS

Estas execuções demonstram que a verificação automática distingue código conforme de código que viola a convenção estabelecida.

## 4. Limitações do Checkstyle

O Checkstyle consegue verificar automaticamente se os identificadores respeitam uma determinada convenção sintática, mas não consegue avaliar se os nomes escolhidos são claros ou semanticamente adequados. Um método pode respeitar o padrão lowerCamelCase e, ainda assim, ter um nome pouco significativo. Por esse motivo, a análise automática deve ser complementada por revisão humana.
