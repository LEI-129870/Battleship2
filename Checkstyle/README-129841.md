# Checkstyle — Convenções de nomes de métodos

**Aluno:** 129841  
**Regra:** MethodName

## Objetivo

Configurar um quality gate no GitHub Actions para verificar se os nomes dos métodos Java respeitam a convenção lowerCamelCase.

## Configuração

Foi criado o ficheiro `checkstyle-129841.xml`, utilizando a regra `MethodName` e a expressão regular `^[a-z][a-zA-Z0-9]*$`.

O workflow `.github/workflows/checkstyle-129841.yml` executa a análise automaticamente nos pull requests.

## Evidências — Red → Green

### Execução vermelha

Foi introduzido um método com um nome inválido, `CalcularPontos()`, que viola a convenção definida.

O Checkstyle identificou a violação e o quality gate falhou.

[Execução vermelha — Checkstyle](https://github.com/LEI-129870/Battleship2/actions/runs/41923751253)

### Execução verde

O método foi corrigido para `calcularPontos()`, respeitando a convenção lowerCamelCase.

Após a correção, o quality gate passou.

[Execução verde — Checkstyle](https://github.com/LEI-129870/Battleship2/actions/runs/41924151917)

## Limitações

O Checkstyle verifica se os nomes respeitam o padrão definido, mas não consegue determinar se um nome é claro ou significativo. Um método pode ter um nome válido e, mesmo assim, não representar corretamente a sua funcionalidade. Por isso, a ferramenta deve ser complementada por uma revisão humana.
